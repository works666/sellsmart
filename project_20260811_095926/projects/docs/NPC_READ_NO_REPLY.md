# NPC 已读不回

## 产品规则

五人版微信和邮件允许 AI 根据人物职责、关系、当前意愿与交流历史选择回复或已读不回。不设置固定沉默概率，也不设置连续沉默后的必回次数。电话、好友申请和拜访保持原流程。

- 成功发送照常消耗行动点。沉默本身不加分或扣分，评估器根据玩家内容判断关系影响和有效接触。
- 微信显示“已读”，邮件显示“已阅读”，不创建空白或省略号 NPC 气泡。
- 正文阅读与附件查看独立。没有查看的附件正文不会进入 NPC 上下文。
- 沉默不构成同意、拒绝、预约确认或 NPC 承诺，不披露线索。合规红线仍明确拒绝。
- 每条新消息重新判断，补充有效信息不保证得到回复。首版不自动补回，也没有未读或等待队列。

## 实现边界

微信和邮件在现有生成调用中同时决定行为和可选正文，随后使用独立评估调用。服务端检查结构化结果后提交状态；前端仅在回复分支创建 NPC 消息。

公共行为字段为 `responseAction: reply | read_no_reply`；沉默时 `content: null`、`invitationStatus: none`，禁止预约。阅读状态与玩家消息 ID 用于显示和恢复。原因代码及证据留在服务端，不返回普通玩家响应。

消息失败不会伪装成已读不回。重试复用原命令，成功重放不重复评分、消息或行动点。预览仍为进程内会话，不提供跨服务重启或多实例持久化。

## 验收方法

确定性测试覆盖两个渠道、表情包、附件、非法输出、评估失败、版本冲突、首请求与后续重试、记忆来源、预约和阅读标记恢复。真实模型矩阵覆盖五位人物 × 两个渠道 × 六轮连续场景；只检查语境和契约，不要求固定沉默比例。

模型质量检查应区分“合法沉默”和“是否适合角色”。合约测试通过不能证明所有人物表现已经调优；真实测试结果必须保留成功、错误和语义观察。
