## 4. 功能地图

### 4.1 三条状态链（重要，别混淆）

| 链路 | 入口 | 权威存储 | 用途 |
|---|---|---|---|
| 正式对局 | `/game` | `game_sessions` + 命令 reducer + `game_runtime_states` | 玩家真实存档、结算、复盘 |
| 五人预览 | `/project-one-preview` | `project_one_preview_sessions/commands` + 浏览器按用户分区的 UI 快照 | 设计师/测试用，**不是正式存档** |
| 设计师后台 | `/designer/*` | `designer_prompt_configs`、素材表、Supabase Storage | 配置提示词、人物、活动门槛、素材 |

页面存在 ≠ 后端已接通：`/knowledge` 上传、真实短信登录、企业认证/归属、实时多人广播仍是缺口（见 `harness/issues/ISSUE_REGISTER.md`）。

### 4.2 页面分组

- 入口与身份：`/`、`/about`、`/login`（演示登录）、`/home`、`/setup`
- 正式玩法：`/start` → `/game` → `/result`、`/ranking`
- 设计/预览：`/project-one-preview`、`/designer` 及 13 个 `/designer/*` 子页
- 其他角色：`/coach`、`/enterprise-admin`、`/room`（"暂未开放"）、`/knowledge`

### 4.3 后端要点

- 对局状态由**服务端版本化命令**写入，AI 只产出结构化 JSON，最终由确定性代码校验/落库；前端不持有 service-role key。

## 6. 数据库连通性（已解决：走本机代理 65532）

**问题**：本网络**直连** `*.supabase.co` 会被重置，表现为 `/api/health/startup` 返回 `503 {"database":"unavailable"}`。

**直连实测证据**（其余站点同时正常，排除断网/密钥问题）：

| 目标 | 直连结果 |
|---|---|
| `https://registry.npmmirror.com` | 200 |
| `https://api.deepseek.com` | 200（配 Key 后） |
| `https://github.com`、`https://www.google.com` | 200 |
| `https://api.supabase.com` | 200 |
| `https://yfmxmgcymuqczpcgjdtb.supabase.co`（本项目库） | **TLS 握手被重置**（curl 35 / Node ECONNRESET） |
| 80 端口 HTTP 直连 | 空回复 |

**解决办法**：本机代理客户端在 `127.0.0.1:65532`（系统代理已指向它）提供 HTTP CONNECT 隧道。给 Node 进程设置代理变量 + `NODE_USE_ENV_PROXY=1` 后：

- `pnpm`/`tsx` 的 `check-runtime-services.ts` → `Database connectivity check passed.`
- `/api/health/startup` → `{"app":"weixun-project","buildId":"tJxSmJqTh_VNvAPh-LgqF","database":"ok"}` **200**
- 玩家与设计师接口均返回 200（见第 5 节表格）

`NODE_USE_ENV_PROXY` 是 Node 24+ 才有的开关，作用就是让 `fetch/undici`（supabase-js 底层）遵循 `HTTPS_PROXY`。**只设 `HTTPS_PROXY` 而不设这个开关是无效的**，这是最容易踩的坑。

> 说明：`*.supabase.co` 被重置这件事与代码无关，`harness/STATE.md` 的 `NET-001`（2026-10-27）记录过同样现象（直连 32 次全失败、经 7897 代理 16 次全 200）。

## 7. 日常启动方式

### 首选：`start-project-with-proxy.bat`（本次新增，已在项目根目录）

双击即可。脚本会：

1. 从 Windows 系统代理读端口（你现在是 `http://127.0.0.1:65532`），读不到则退回 `http://127.0.0.1:7897`；
2. 设置 `HTTP_PROXY / HTTPS_PROXY / ALL_PROXY / NO_PROXY` 与 `NODE_USE_ENV_PROXY=1`；
3. 调用原来的 `start-project.bat`：环境自检 → 数据库自检 → 构建新鲜度检查 → 找可用端口 → 启动并打开浏览器。

端口不对时可显式指定：

```bat
start-project-with-proxy.bat http://127.0.0.1:7890
```

### 什么时候可以直接用原来的 `start-project.bat`

只有当 `*.supabase.co` 能直连时（例如代理客户端开了 TUN/全局模式、或换到校园网/公司网）。否则它会在 `[2/4] Checking database connectivity` 一步失败退出——这不是脚本坏了，是网络门禁。

### 快速自查

```powershell
curl.exe http://127.0.0.1:5000/api/health/startup   # 期望 database":"ok" 且 200
```

### 备用命令（不经过启动器）

```powershell
cd projects
$env:HTTPS_PROXY="http://127.0.0.1:65532"; $env:NODE_USE_ENV_PROXY="1"
$env:PORT=5000; $env:NODE_ENV="production"
node dist\server.js
```

### 如果哪天数据库又变成 unavailable

按顺序排查：① 代理客户端是否还开着、端口是否变了（`GET` 系统代理设置或用 `start-project-with-proxy.bat http://127.0.0.1:<新端口>`）；② `curl.exe -x http://127.0.0.1:65532 https://<ref>.supabase.co/rest/v1/` 是否返回 401（401 说明隧道通了，只是没带 apikey，属于正常）；③ Supabase 项目是否被暂停；④ 最后才怀疑密钥（`pnpm local:check` 会告诉你变量是否缺失，且不打印值）。

```powershell
corepack pnpm local:check          # 环境变量体检（不打印密钥）
corepack pnpm dev                  # 开发模式（tsx watch，默认 5000）
corepack pnpm build                # next build + tsup 服务端打包

corepack pnpm test:game-state      # 对局状态专项
cd ..; ./scripts/harness-check.ps1 # 治理台账结构检查（改代码后必跑）
```

启动器行为：`start-project.bat` 会先跑 `check-local-env` → `check-runtime-services`（**DB 不通会直接失败退出**）→ 按源码时间判断是否需要重建 → 端口 5000 被占用且构建号不符时自动试 5001、5002…。

1. **登录是演示实现**：任意 4–6 位验证码可通过，账号密码也不校验，绝不能对外部署当真实认证。
2. **密钥**：`projects/.env.local` 含真实 Key，已被 `.gitignore` 忽略；不要提交、不要贴进聊天/截图。本次只读校验，未打印任何密钥值。
3. **台账真实性**：`AGENTS.md` 要求改代码必须同批更新 `STATE / CURRENT_ITERATION / ISSUE_REGISTER / HANDOFF` 并跑 `harness-check.ps1`；不要只凭台账判断功能有没有做，先查代码/迁移/数据库。
4. **数据快照不是事务备份**：`data/manifest.json` 是逐表 REST 逻辑导出，恢复前后要核对 `count_verified` 与对象 SHA-256。
5. **节点选择**：日常从 `start-project.bat`（或带代理版）走生产构建；调试用 `pnpm dev`；两者不要同时占 5000。
