## C. 远程数据库逻辑备份步骤

下面命令以 Supabase CLI 官方文档为准。由有权读取源项目的维护人执行；应先用组织允许的方式完成 CLI 登录并链接**准确的开发项目**。只在受控机器的临时备份目录执行，并确保导出文件受 ACL/磁盘加密保护。

```powershell
cd .\projects
supabase login
supabase link --project-ref <经核验的项目引用>
supabase migration list --linked
New-Item -ItemType Directory -Force .\handover-backup | Out-Null
supabase db dump --linked --schema public --file .\handover-backup\public-schema.sql
supabase db dump --linked --schema public --data-only --use-copy --file .\handover-backup\public-data.sql
```

注意事项：

1. 先检查 `supabase migration list --linked`，并记录待推送/远程超前的迁移；备份前不要擅自 `db push` 或 `db reset --linked`。
2. `db dump` 默认只导出 schema，不导出数据。`--data-only` 才输出行数据。schema 和 data 两份必须来自同一快照时间窗口。
3. Supabase CLI 会省略托管 `auth`、`storage` 和扩展相关 schema。需单独制定 Auth 用户迁移方式；不要把 `auth.users` 原样拷贝到不支持的目标项目。
4. Storage 数据库元信息和对象文件是两件事。逐个列出使用中的 bucket；另行下载对象、记录 bucket 名称/对象 key/元数据、对象数量/总大小和校验哈希。若应用还有外部 S3 配置，也要由管理员确认 bucket 与区域，不能只读本地 `.env.example` 推断实际使用服务。
5. 数据导出可能含手机号、玩家对话、提示词和业务资料。仅按授权范围导出，使用加密存储并限制接收人；生成公开仓库 commit 前再次确认 dump 未被 Git 跟踪。
6. 导出后保留 `schema.sql`、`data.sql` 文件大小、SHA-256、导出 UTC 时间、项目非密钥标识、记录数和执行人。不要把 connection string 或数据库密码放进清单。

官方说明：[Supabase CLI 数据库备份与恢复](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore)、[Supabase CLI `db dump` 参考](https://supabase.com/docs/reference/cli/supabase-db-dump)。

## D. Storage 对象交接

Supabase 数据库 dump 不包含 Storage 二进制对象。当前代码有设计师人物图片/场景图片读取和上传入口，数据库也定义了相关元数据。操作前先按 `projects/src/app/api/designer/image-assets/`、`scene-assets/` 和实际 Storage 调用搜索 bucket 使用，并从 Dashboard/CLI/API 导出对象清单。对每个对象保存：bucket、对象 key、MIME、大小、最后更新时间、SHA-256；对象名和链接不得因迁移随意改动。

将原 bucket 复制到一个新的**隔离目标 bucket**，恢复元信息并验证 UI 图片能打开，再切换新测试环境配置。切换生产 Bucket 或 Supabase 数据前先在新项目做恢复演练并检查政策/RLS。Storage 备份参考：[下载对象](https://supabase.com/docs/guides/storage/management/download-objects) 和 [Storage 管理](https://supabase.com/docs/guides/storage)。
