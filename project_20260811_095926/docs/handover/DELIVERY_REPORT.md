备份是读取窗口内的 REST 逻辑副本，**不是事务一致的 PostgreSQL 整库镜像**。它覆盖服务密钥可访问且 PostgREST 暴露的业务表、Auth 用户元数据与 Storage 原文件；不包含数据库密码、认证 token、供应商 API key、Supabase 平台配置、未暴露的私有 schema 或数据库服务器级状态。表结构、RPC、RLS 等以仓库迁移文件交接，未额外取得远程 DDL dump，亦未在新项目进行真实恢复演练。

原浏览器 localStorage、尚未保存到服务端的页面草稿、只存在当前网页内存中且未下载的系统评测报告不属于数据库副本；需要继续原浏览器临时进度时，由原使用者自行导出或保留原浏览器环境。API key 等凭据由接手人另行配置。

## 接手操作顺序

1. 先核对 ZIP 的 `.sha256`，解压后读包根目录 `README.md`，再读本目录 [README.md](README.md)。
2. 在目标环境安装 Node.js 22+ 和 pnpm 9；复制非敏感配置模板并由管理员配置新的 key/secret。
3. 若继续使用原 Supabase，无需导入副本；如迁移到新项目，先读 [DATA_RESTORE.md](DATA_RESTORE.md)，执行 `--verify-only`，应用迁移，再做数据库和 Storage dry-run。
4. 隔离目标恢复验证后构建启动，按 [页面与接口清单.md](页面与接口清单.md) 验收各角色入口。
5. 后续事项以 `harness/issues/ISSUE_REGISTER.md` 为准，尤其是演示认证、正式多人同步、旧 UI 测试和真实模型验收边界。
