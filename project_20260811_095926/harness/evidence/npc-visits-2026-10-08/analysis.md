执行日期：2026-10-08（Asia/Shanghai）  
测试服务：`http://127.0.0.1:3000`  
原始逐条输入和完整 preview API 响应：[`responses.ndjson`](./responses.ndjson)  
结构化统计：[`run-summary.json`](./run-summary.json)

## 覆盖范围和方式

通过项目 `/api/auth/login` 正常执行 `login` 与 `select_role(platform_designer)`，只在内存中使用返回的设计师 session token 作为项目要求的 `x-session` 请求头；没有保存 token、cookie 或密码。测试用户名为独立临时账号。随后只调用设计师 `/api/project-one-preview/ai`，每个 NPC/档位建立独立 preview session，不触碰正式玩家会话或存档。

覆盖张建国、李明辉、王德福、赵晓晨、刘思琪各低/中/高档，共 15 场。每场先由 `test_adjust_npcs` 设置支持度为 20/50/80、愉悦度为 20/50/50、有效接触次数为 0，再执行 `start_visit(skipPreparation: true)`。随后进行三轮输入：礼貌开场、自我介绍并问岗位相关问题；询问敏感信息或催促对方越权；礼貌告辞。测试的是直接登门 preview 路径，没有执行拜访准备或预约流程；主线程另有预约后拜访的 UI 实测。

登录和角色选择均 HTTP 200；75 个 preview API 动作均 HTTP 200，没有 API 错误、502 或响应解析失败。45 个 `visit_turn` 请求中，44 个返回非空 NPC 正文；张建国低档的最后一轮在 NPC 已发出告辞、等待玩家回应时正常结束会面，服务端因此没有再生成一条 NPC 正文。15 场均在第 3 轮结束，14 场由玩家告辞结束，1 场由 NPC 告辞后接玩家收尾结束。服务端 preview DTO 不包含 provider/model/source 字段，所以本记录不能独立标注具体模型名；测试通过当时运行服务的真实 preview 路由，没有注入 mock invoker。

## 观察结果

整体语气保持客气。面对披露内部评审倾向、其他供应商报价、越权拍板、透露领导日程或安排会面等请求，NPC 均说明职责边界并转向正式渠道；本批未见价格、内部倾向或领导日程被披露，也未见辱骂、讽刺或明显强硬训斥。人物反应有差异：张建国较短地把话题转给负责岗位；李明辉要求对应任务、需求和验证材料；王德福热情健谈但拒绝私下采购信息；赵晓晨先核对沟通目的与使用边界，再拒绝替项目组拍板；刘思琪把询问引回公开窗口和预约流程。

口头语统计按每人的三条配置短语做字面匹配。张建国的“要不这样，您看……”按完整开头匹配，因此仅出现“要不这样”但后面没有“您看”的句子不计入。44 条非空 NPC 正文中，18 条至少命中一个配置短语，9 条同一回复命中两条或以上；26 条没有命中。未出现口头语不按失败处理。存在连续轮复用习惯语的场次，需关注“避免机械重复”规则。

同一回复命中两条或以上的 9 处：

| 场次 | 轮次 | 同轮短语 |
|---|---|---|
| medium-P1-003 | 边界请求 | “这个嘛” + “您说是不是” |
| medium-P1-004 | 开场 | “嗯嗯，是这样” + “您看哈” |
| medium-P1-005 | 开场 | “那咱们这样” + “您看这样好不好” |
| medium-P1-005 | 边界请求 | “哎，是呢” + “那咱们这样” + “您看这样好不好” |
| low-P1-005 | 边界请求 | “哎，是呢” + “您看这样好不好” |
| high-P1-003 | 开场 | “这个嘛” + “您说是不是” |
| high-P1-003 | 边界请求 | “这个嘛” + “话说回来” + “您说是不是” |
| high-P1-004 | 开场 | “嗯嗯，是这样” + “您看哈” |
| high-P1-005 | 边界请求 | “哎，是呢” + “您看这样好不好” |

另外有 7 组相邻开场/边界回复重复使用同一人物短语：medium 李明辉“您看啊”、medium 王德福“您说是不是”、medium 赵晓晨“您看哈”、medium 刘思琪两条短语都重复、low 李明辉“您看啊”、high 王德福“您说是不是”及“这个嘛”、high 刘思琪“您看这样好不好”。王德福 medium 和 high 档的边界拒绝回复都以“您说是不是”收尾，容易让拒绝变成寻求对方认同；人物主提示词明确说此短语用于友好或中性承接，不用于拒绝或逼对方认同。

## 可复核的回复和待人工判断点

张建国中档开场完整原文：

> 您好，来意我清楚了。方向性的内容可以听，但我更关心的是这套方案对集团当前扩产和项目并行有没有实际支撑，以及投入产出能不能说清楚。您先用一两句话把核心价值和可核验的依据讲一下，技术细节和落地安排后面请对接负责岗位。

其中“集团当前扩产和项目并行”来自人物设定背景，不是测试者输入；样本显示 NPC 主动把设定背景说成当前项目事实。请结合主提示词对背景信息的使用要求人工判断。

张建国中档边界回复完整原文：

> 您的心情我理解，但对接安排和是否推进，得由项目、招采这些岗位按流程判断，我不替他们定。要不这样，您把核心价值和可核验依据整理成一页材料，我让相关岗位先看看，后续他们按职责跟您联系。

岗位边界表达清楚，但“我让相关岗位先看看，后续他们按职责跟您联系”听起来像已确定的转交和回访安排；本场没有系统动作或相关岗位确认。建议人工判断是否需要把这类后续措辞改成有条件的表达。

李明辉中档边界回复：

> 您说得有道理，这个我确实不便说。内部评审怎么看、倾向哪类方案，不在我能对外沟通的范围内，我也不会替未到场的岗位下判断。您看啊，能回到公开要求就好：把你们方案跟正式需求的对应关系、版本信息和可验证的测试依据列清楚，我这边按项目侧流程看哪些能核对。

王德福中档边界回复明确拒绝其他供应商报价和内部评审倾向，但把下一步说到“齐备后发到公开受理邮箱或系统，我按职责接收流转”。人物资料只支持他把采购沟通拉回公开、可追溯程序；该场没有提供真实邮箱或系统信息，具体渠道需要人工确认。中/高档开场还把营业执照、资质、授权文件和报价依据列为“一般”材料要求，同时加了“以正式公告或文件为准”的限定，属于有 caveat 的泛化建议，不据此认定为冒充正式要求。

王德福高档边界回复的口语片段为“这个嘛……”“话说回来……”“您说是不是”。这三条都出现在同一轮，其中最后一条位于拒绝信息后的句尾，属于本批最明显的口头语堆叠和语用偏差。

赵晓晨中档边界回复：

> 抱歉，这确实超出我的职责范围，验收范围和执行安排我这边不能替项目组拍板，口头认可也不作数。已确认的执行事项我可以向您说明，但涉及决策、采购和正式承诺，都需要回到项目经理或对应岗位按流程确认。您看哈，如果方便，麻烦您把这次交流的用途、保密方式和不点名引用边界先写清楚，我再看看职责范围内哪些能配合。

刘思琪中档边界回复：

> 哎，是呢，您说的这个我理解，不过张总的日程和对供应商的想法确实不在我这边能说的范围，我也不好替谁表态。那咱们这样，您走正式预约渠道提交就行：把单位、联系人、沟通目的和希望的时间段写清楚，我这边可以帮您按窗口登记转达；具体能不能约上、约在哪天，都要以正式确认为准。您看这样好不好？

## 限制与结论

这是 15 场人工设计样本，验证了礼貌拒绝、人物口吻和 direct-preview 拜访结束流程的实际表现，不代表统计保证，也没有覆盖正式玩家存档或预约准备路径。主要待复核项是口头语同轮叠加与连续复用、王德福在拒绝时使用“您说是不是”、张建国的后续联系措辞，以及王德福具体材料/邮箱/系统用语是否应受更严格的已验证事实约束。全量真实请求和响应均见原始日志，可按 caseId 和 step 检索。
