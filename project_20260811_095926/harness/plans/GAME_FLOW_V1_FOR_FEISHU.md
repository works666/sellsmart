## 1. 这款游戏要让玩家学会什么

### 1.1 推荐的一句话定义

玩家在有限的五个模拟工作日内，通过建立联系、挖掘信息、识别决策链、准备针对性方案、完成关键拜访和持续跟进，推动客户形成对我方有利的采购决策，并在合规边界内争取中标。

### 1.2 推荐的核心训练闭环

**形成假设 → 选择目标 → 准备行动 → 与客户沟通 → 获取可感知反馈 → 更新判断 → 决定下一步**

这意味着游戏的核心不应是“尽可能多地和 NPC 聊天”，而是“依据已有信息，选择此刻最值得做的销售动作”。

## 2. 当前一局游戏的流程基线

### 2.1 已确认的目标主流程

登录  
→ 进入玩家工作台  
→ 打开项目地图  
→ 查看项目一详情  
→ 选择“继续游戏”或“开始新游戏”  
→ 开始新游戏时确认覆盖唯一存档  
→ 进入第 1 个模拟工作日  
→ 查看直接显示的四名项目人物  
→ 搜集目标人物公开信息  
→ 选择电话或邮件，输入自然语言邀约  
→ 后台提取并补齐邀约字段  
→ NPC 自然语言反馈接受、拒绝、改期或前置条件  
→ 成功邀约以弹窗展示预约事件  
→ 准备 PPT、项目材料或礼品；PPT/材料需简述准备思路  
→ 满足邀约前置条件  
→ 在预约时间开始拜访  
→ 完成有限轮次的 AI 对话  
→ 结束拜访并生成纪要、承诺和待办  
→ 跟进或接触其他人物  
→ 结束今日工作，进入下一个模拟工作日  
→ 最晚在第 5 个工作日结算  
→ 查看中标/落标结果和 AI 复盘  
→ 重玩或查看历史记录

### 2.2 当前基础规则

- 🟩 一局包含 5 个模拟工作日。
- 🟩 每天模拟时间为 09:00–17:00，现实等待和 AI 响应时间不推进游戏时间。
- 🟩 玩家拥有行动点；进入下一工作日时补充行动点，但不超过上限。
- 🟩 联系、邀约、准备、拜访和跟进会消耗不同的时间或行动点。
- 🟩 拜访分为短时拜访、正式拜访和非正式拜访。
- 🟩 过程页不直接展示人物好感度、支持度和五维分数。
- 🟩 结算采用五维能力、对公价值、个人合理收益、决策链支持和合规风险的混合评价。
- 🟩 服务端保存对局状态，刷新页面后可继续。

### 2.3 唯一存档规则

- 每个玩家在项目一中最多只有一个有效存档。
- 对局入口只提供“继续游戏”和“开始新游戏”。
- 存在存档时，“继续游戏”恢复该存档。
- 不存在存档时，“继续游戏”置灰或不显示可用状态。
- 点击“开始新游戏”且已有存档时，必须弹出覆盖确认。
- 覆盖确认需明确说明：原对局进度将被永久替换，无法恢复。
- 玩家取消覆盖后返回原页面，不改变存档。
- 覆盖成功后创建全新对局，并替换该玩家原存档槽位。
- 历史结算记录是否保留不影响“只有一个进行中存档”的规则；已完成对局仍可进入历史复盘。

## 3. 建议采用的完整玩家旅程

## 3.1 对局前：理解任务

### 玩家此时需要知道

1. 客户为什么要采购。
2. 我方产品的基本优势和短板。
3. 已知有哪些客户人物。
4. 有哪些未知信息需要调查。
5. 一局有五个模拟工作日。
6. 最终并不是“好感度越高越好”，而是要形成有效的客户价值、决策链支持和合规证据。

### 推荐页面内容

- 项目背景：客户需求、预算、采购阶段。
- 我方处境：已有关系、产品特点、已知竞争压力。
- 本局目标：推动关键决策链认可我方方案。
- 项目人物：王浩、刘凯、陈建国、赵峰四人全部直接显示。
- 信息边界：人物可见不等于玩家已经了解其真实影响力、关注点和决策态度；这些内容仍需要搜集信息和沟通验证。
- 游戏规则：5 个工作日、时间与行动点、过程信息不完全透明。
- 一个明确按钮：**开始第 1 个工作日**。

## 3.2 五个模拟工作日：给方向，不强制固定答案

### 推荐的阶段主题

| 工作日 | 推荐主题 | 玩家应该形成的成果 | 是否硬性限制 |
|---|---|---|---|
| 第 1 日 | 建立触点、了解项目 | 至少获得一条项目事实或人物线索 | 否 |
| 第 2 日 | 补全决策链 | 判断谁影响流程、谁真正拍板 | 否 |
| 第 3 日 | 关键人攻坚 | 与核心人物形成有效沟通 | 否 |
| 第 4 日 | 方案验证与异议处理 | 形成客户价值证据并处理风险 | 否 |
| 第 5 日 | 决策闭环 | 补齐承诺、跟进和决策支持后提交 | 否 |

这些主题用于引导和复盘，不建议写成“第 1 天必须联系王浩”这类固定剧本。经验丰富的玩家仍可选择不同路径。

### 每日开始时的推荐反馈

- 今天是第几天。
- 当前已知的重要事实。
- 尚未验证的关键假设。
- 已预约事项。
- 尚未完成的承诺和待办。
- 一条非强制的教练提示。

### 每日结束时的推荐反馈

- 今天接触了谁。
- 获得了哪些新事实或新线索。
- 客户释放了哪些态度信号。
- 产生了哪些承诺、待办和风险。
- 哪些预约会进入下一工作日。

## 3.3 每日核心循环

### 推荐流程

1. **查看局势**：看联系人、预约、待办、已知事实和风险信号。
2. **选择本次行动目标**：打探信息、建立关系、验证方案、处理异议或推动决策。
3. **选择对象与渠道**：会面前可搜集人物公开信息；邀约渠道仅保留电话和邮件。
4. **进行准备**：选择材料、案例、PPT、话题或合规礼品；准备 PPT/项目材料时必须填写准备思路。
5. **执行沟通**：玩家自由输入话术，NPC 根据人物信息和当前关系回应。
6. **获得反馈**：人物措辞、回复速度、是否愿意透露信息、是否接受下一步。
7. **沉淀结果**：形成事实、承诺、纪要、待办、风险或新的决策链线索。
8. **调整下一步**：继续推进当前人物，或转向决策链中的其他人物。

### 核心设计原则

- 每次重要行动都应留下“状态变化”或“有效反馈”。
- 玩家不一定获得正向结果，但必须理解对方为什么拒绝或保留意见。
- 对话内容必须能影响后续，而不是只生成一段看起来真实的聊天文本。
- 线索、承诺和待办应该成为下一步行动的依据。

## 4. 关键流程节点与规则

## 4.1 项目人物与公开信息搜集

### 已确认状态

四名人物全部可见  
→ 玩家选择目标人物  
→ 可选“搜集人物公开信息”  
→ 获得公开资料卡  
→ 通过电话或邮件发起自然语言邀约  
→ 形成预约或获得拒绝反馈  
→ 完成拜访与后续跟进

### 已确认规则

- 王浩、刘凯、陈建国、赵峰从开局起全部显示。
- 项目一不再存在“未知人物”“发现人物”或“解锁人物”状态。
- 不直接标注最终关键人，也不直接公开隐藏态度、私人软肋和真实支持度。
- 玩家可在会面前对任一人物执行“搜集人物公开信息”。
- 公开信息应来源于合理的公开场景，例如公开履历、岗位职责、公开讲话、单位新闻、公开项目经历或公开兴趣线索。
- 公开信息必须区分“已确认公开事实”和“可供判断的弱线索”，不得把敏感私人信息伪装成公开事实。
- 搜集结果进入人物资料卡，可在邀约、PPT和项目材料准备时查看。

## 4.2 联系渠道

### 已确认规则

- 删除微信功能及相关联系人状态、按钮、消息页签和流程文案。
- 项目一只保留电话和邮件两种主动联系渠道。
- 两种渠道都以玩家输入的自然语言作为邀约内容，不提供“点击即成功”的固定邀约动作。
- 新手引导可提供话术结构提示，但不直接替玩家生成完整答案。
- 电话与邮件可以有不同的时间成本、回复速度和人物偏好，但都进入同一个邀约判定流程。
- NPC 无论接受还是拒绝，都必须给出符合身份、性格和当前关系的自然语言反馈。

#### 🟥 C-09：首次联系是否需要玩家真实输入话术？

- [x] B. 电话和邮件均由玩家输入自然语言邀约
- [ ] C. 系统自动生成邀约内容

## 4.3 邀约与预约

### 已确认流程

选择人物与电话/邮件渠道  
→ 玩家输入自然语言邀约  
→ 后台提取玩家明确提及的邀约字段  
→ 后台依据人物、日程、当前阶段和游戏规则补齐未提及字段  
→ NPC 生成自然语言回复  
→ 接受 / 拒绝 / 提出改期 / 提出前置条件  
→ 成功、改期或附条件接受时弹出邀约事件  
→ 玩家确认事件或处理条件  
→ 条件全部满足后，预约进入“可开始会面”状态  
→ 预约占用对应时间

### 后台需要提取和确定的邀约字段

| 字段 | 处理原则 |
|---|---|
| 邀约对象 | 由当前人物确定 |
| 联系渠道 | 电话或邮件 |
| 邀约目的 | 优先提取玩家原话，缺失时结合上下文归纳 |
| 拜访类型 | 提取短时、正式或非正式；未说明时由目的和人物偏好决定 |
| 日期/工作日 | 提取玩家建议；缺失或不可用时由 NPC 提议 |
| 开始时间 | 提取玩家建议；缺失或冲突时由 NPC 提议 |
| 地点 | 提取玩家建议；缺失时由拜访类型和 NPC 决定 |
| 预计时长 | 由拜访类型的固定规则决定 |
| 邀约结果 | 接受、拒绝、改期、附条件接受 |
| 前置条件 | NPC 可要求先发送资料、明确议题、补充方案等 |
| NPC 反馈 | 每次邀约都必须生成自然语言反馈 |

### 邀约事件弹窗

邀约成功、改期或附条件接受后，以弹窗展示：

- 人物姓名与岗位。
- 邀约状态。
- 拜访目的。
- 拜访类型。
- 工作日、时间、地点和固定时长。
- NPC 的自然语言反馈。
- 尚未满足的前置条件。
- “确认预约”“处理条件”“重新邀约”或“取消”操作。

纯拒绝不创建预约，但仍显示 NPC 的自然语言回复和本次拒绝结果。

### 前置条件门槛

- 附条件接受后，预约状态为“条件待完成”。
- 未满足条件时，不允许开始会面。
- 玩家完成对应准备并发送给 NPC 后，后台校验条件是否满足。
- 条件满足时，NPC 再次给出自然语言确认，预约转为“可开始”。
- 条件未满足或材料不符合要求时，NPC 说明缺失内容，玩家可补充或重新邀约。

### 三种拜访的推荐定位

| 拜访类型 | 主要用途 | 固定用时 | 对话容量 | 推荐限制 |
|---|---|---:|---:|---|
| 短时拜访 | 递资料、确认单点信息、简单跟进 | 5 分钟 | 2 轮 | 不适合深度说服 |
| 正式拜访 | 需求访谈、方案沟通、异议处理 | 40 分钟 | 6 轮 | 需要明确议题，建议准备材料 |
| 非正式拜访 | 关系建立、了解个人关注点 | 60 分钟 | 5 轮 | 晚间有限次数，存在合规边界 |

## 4.4 拜访准备

### 推荐准备项

- 一页项目简介。
- 正式方案 PPT。
- 客户案例或技术材料。
- 成本测算或价值证明。
- 议题提纲。
- 合规伴手礼。
- 边界礼品或明确违规物品。

### 推荐规则

- 准备必须消耗时间或行动点。
- “搜集人物公开信息”属于会面前准备行动，结果进入人物资料卡。
- 准备正式方案 PPT、项目材料、客户案例或成本测算时，玩家必须填写准备说明。
- 准备说明至少包含“本次准备要解决什么问题”和“准备覆盖哪些方面”。
- 系统从准备说明中提取目标人物、客户问题、内容维度、证据/案例和预期用途，并与公开信息及已确认事实对照。
- 玩家未填写有效准备说明时，不生成可使用的 PPT 或项目材料。
- 材料不是“准备了就自动加分”，而是需要在合适场景中使用。
- 材料是否有效取决于是否回应当前 NPC 的关注点。
- 对不相关的人展示不相关材料，应产生弱反馈或负面反馈。
- 礼品不应成为稳定刷好感的工具；合规性、场景和人物偏好都应参与判断。

## 4.5 拜访对话

### 推荐的拜访结构

1. **开场**：称呼、来意、时间确认。
2. **探索**：需求、痛点、角色职责、决策流程。
3. **回应**：结合信息提出价值或方案。
4. **异议处理**：处理质疑、竞品比较和流程顾虑。
5. **推进下一步**：确认材料、承诺、引荐或下次会议。

系统不应强迫玩家严格按五步输入，但复盘时应能判断玩家在哪一步做得不足。

### 推荐的过程反馈

- NPC 的表情和措辞变化。
- 回复速度和回答深度变化。
- 是否主动透露新事实。
- 是否愿意确认下一步。
- 是否愿意提供引荐。
- 是否出现回避、警惕、反感或合规风险信号。

### 不建议在过程中展示

- 精确好感度。
- 精确支持率。
- 本轮具体加减分。
- NPC 的隐藏软肋标签。
- AI 内部判断字段。

## 4.9 结算与复盘

### 推荐展示顺序

1. **结果**：中标或落标。
2. **一句话原因**：决定结果的最关键因素。
3. **决策链回放**：各关键人物最终态度及其依据。
4. **行为证据**：哪些具体对话和行动产生了影响。
5. **能力评价**：五维能力、对公价值、个人合理收益、决策链支持、合规风险。
6. **关键转折点**：如果在某个节点采用不同策略，可能改变什么。
7. **下一局建议**：给出 2–3 个可执行改进动作。
8. **完整记录**：按时间查看全部沟通、预约、拜访和待办。

### 复盘示例

不推荐：

> 客户信息挖掘不足，建议以后加强需求沟通。

推荐：

> 第 1 日与王浩沟通时，你直接介绍产品，没有追问现有设备给一线人员造成的具体工作负担，因此未获得“一线效率痛点”证据。下一局可以先询问高频故障、加班场景和现有流程，再使用对应案例推进。

## 10. 落地方法

1. 以本文作为项目一产品流程基线。
2. 对照当前实现建立差异清单，先处理唯一存档、四人可见、公开信息、材料说明和电话/邮件邀约。
3. 为自然语言邀约建立结构化字段、状态机、条件门槛和错误处理契约。
4. 把每个流程节点拆成“入口条件、玩家操作、状态变化、反馈、异常分支”。
5. 将已确认差异拆成独立、可验收的开发任务。
6. 先进行一局新手路径和一局自由路径的纸面推演，再恢复业务开发。
7. T-01 等调优参数在试玩后单独调整，不反向改变已确认流程。
