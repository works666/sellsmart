# 项目一固定冒烟测试

## 目的

用同一条路径验证“启动 → 建局 → NPC 对话 → 5 轮动作 → 结算 → 刷新恢复”。在项目一纵向闭环完成前，不能只用页面能打开作为验收证据。

## 固定输入

- 项目：项目一（默认/固定难度）
- 模式：单人
- 轮数：5
- 身份：普通玩家
- 场景来源：项目一内置权威内容，不依赖每次随机生成
- 测试账号：使用开发环境专用账号；真实账号和口令不写入仓库

## 步骤与预期

1. 启动服务并访问首页：页面无服务端错误。
2. 登录并选择项目一：创建唯一 `gameSessionId`，服务端状态为第 1 轮。
3. 选择首个可见 NPC 并发送消息：请求包含会话与 NPC 标识，响应属于该 NPC。
4. 切换 NPC 后返回：两名 NPC 的消息历史互不混合。
5. 刷新页面：当前轮次、操作点、已解锁内容和对话恢复。
6. 执行关系动作：操作点只扣减一次，亲密度变化符合服务端规则。
7. 完成 5 轮：不能提前进入第 6 轮，服务端生成确定性结果。
8. 打开结算页：展示本局真实五维评分、关键事件和复盘，不显示固定示例数据。

## 失败记录

每次执行把日期、环境、失败步骤、请求标识和对应问题 ID 写入 `harness/issues/ISSUE_REGISTER.md`。敏感 Header、密钥、完整用户对话不得写入台账。
