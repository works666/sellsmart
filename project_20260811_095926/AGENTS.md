# 项目协作规则

本文件适用于整个项目根目录。`projects/AGENTS.md` 中的工程约束继续适用于应用目录；若两者冲突，以本文件的治理与范围规则优先，以内层文件的技术实现约束补充。

## 开始工作

每次开始前必须阅读：

1. `PROJECT.md`
2. `harness/STATE.md`
3. `harness/plans/CURRENT_ITERATION.md`
4. `harness/issues/ISSUE_REGISTER.md`
5. `harness/memory/DECISIONS.md`
6. 与任务有关的 `harness/context/` 文档

## 范围门

- `CURRENT_ITERATION.md` 中只有标记为“已批准”的条目可以进入实现。
- 发现新问题时先写入 `BACKLOG.md` 或 `FINDINGS.md`，不要自动扩大范围。
- 所有确认的问题必须进入 `ISSUE_REGISTER.md`。问题只改变状态，不删除；未解决问题必须保留原因和下一步。
- 业务资料冲突时停止依赖该规则进行实现，并在 `DECISIONS.md` 新增待决项。

## 台账真实性硬约束

以下规则属于提交与交付硬门，不是建议：

1. **不得只凭台账判断功能是否完成。** 在把任何条目标为“未做”、准备新增实现或修改既有能力前，必须先检查实际代码、路由、数据库迁移、运行数据、存储对象和相关测试；检查范围按该能力实际涉及的层级确定。
2. **先证明缺口，再修改。** 必须记录检查过的实际入口或证据，以及“已完成部分 / 确认缺口 / 本批不动部分”。如果代码已经实现、数据库已有数据或存储已有资产，不得因台账过期而重复建设、覆盖或回退。
3. **外部状态必须查权威源。** 涉及“是否已上传、是否已迁移、是否已配置、是否已生成”等结论时，只看仓库文件或旧文档不够；在具备访问条件时必须读取对应数据库、对象存储或服务端接口。无法访问时必须写明“未实查”，不得改成已确认。
4. **实现与台账必须同批提交。** 只要 `projects/src/`、`projects/supabase/`、`projects/scripts/`、`projects/public/` 或 `projects/package.json` 有实现性变化，本批必须同时更新 `STATE.md`、`CURRENT_ITERATION.md`、`ISSUE_REGISTER.md` 和 `HANDOFF.md`；产生新决定或新事实时还必须更新 `DECISIONS.md` 或 `FINDINGS.md`。
5. **状态只能由证据推动。** `Resolved` 必须附实际实现位置和验证证据；只完成基础设施或部分路径时使用 `In Progress`，并明确剩余缺口。历史记录可保留，但必须标明日期，不能继续作为当前状态引用。
6. **结束前必须做双向复核。** 从“代码/数据库 → 台账”检查有无漏记，再从“台账声称 → 实际实现”检查有无夸大；运行 `scripts/harness-check.ps1`。该脚本失败时不得宣称本批完成。
7. **发现不一致立即纠正。** 台账与实际项目冲突时，以可复核的当前实现和权威外部状态为事实基础，先修正当前状态和问题证据，同时保留历史发生时间；禁止为了让台账显得正确而改坏已经完成的功能。

## 实现要求

- 一个工作项对应一个可验证的用户或系统能力。
- 修改前记录当前行为、目标行为、影响范围和验收条件。
- 优先修复端到端契约，避免只做页面表象。
- AI 输出影响游戏状态时必须使用结构化契约，并由确定性代码校验。
- NPC 对话、轮次、线索、分数等状态必须以服务端会话为权威来源。
- 不提交密钥、真实账号、`.env` 或临时调试输出。

## 结束工作

每批有意义的修改必须：

1. 执行与风险相称的验证。
2. 更新 `harness/STATE.md`。
3. 把新决定写入 `DECISIONS.md`，把新发现写入 `FINDINGS.md`。
4. 更新当前迭代条目状态和证据。
5. 更新 `ISSUE_REGISTER.md` 的状态、证据、阻塞原因和最后检查日期。
6. 在 `HANDOFF.md` 留下可由下一位开发者直接继续的信息。
7. 对照“台账真实性硬约束”完成实际项目与台账的双向复核，并运行 `scripts/harness-check.ps1`；未通过不得交付。

## Git

- 提交应聚焦一个工作项，使用 `type(scope): summary` 格式。
- 推荐类型：`chore`、`docs`、`fix`、`feat`、`refactor`、`test`。
- 不重写他人历史，不使用破坏性重置。
- 范围确认前只允许治理、文档、诊断和基线提交。
